# 텍스트판 규격 v1

기준일 2026-10-30 · 적용 2026-11-02 MORNING Vol.27(예비호 ③)부터 · 근거: 창간 전 개선 계획 v1 5·8번, 헌장 v1.1 · 초안 Claude 편집국 · 결정 발행인
대상은 MORNING이다. 다른 지면도 같은 틀을 빌려 쓸 수 있고, 지면별 차이는 각 desks/ 파일이 정한다.

## 1. 텍스트판이 하는 일

- 지면의 3분 층이다. 휴대폰에서 본문을 읽는 곳이고, 보고서로 옮기는 곳이며, 검색되는 곳이다.
- 이미지(1면)에 있는 사실은 모두 텍스트판에 있다. 텍스트판에 없는 사실을 이미지에 더하지 않는다.
- 형식(마크다운이든 HTML이든)과 관계없이 아래의 순서, 칸 이름, 신호 id를 지킨다.

## 2. 순서 (고정)

| 차례 | 칸 | 필수 | 내용 |
|---|---|---|---|
| 0 | 머리줄 | 필수 | 제호 · 제N호 · Vol.N · 날짜(요일) · 예비호·창간호 표기 |
| 1 | 1분 읽기 | 필수 | 세 줄 (5절) |
| 2 | 신호 s1~s3 | 필수 | 신호마다: 제목 · 촉 · 읽기 · 옮겨 볼 조건(11/3부터) · 침 · 닿는 공약 · 원문 링크와 발표일. 갈린 경우에만 두 시선 한두 줄 |
| 3 | JUNGNANG Q | 필수 | 열린 물음 하나 |
| 4 | 권하는 것 · 피하면 좋은 것 | 근거 있을 때 | 각 한 문장 |
| 5 | SIGNAL PROMPT · ROUTE | 필수 | 입력문 하나, KEEP/NEW/WATCH와 다음 자리 |
| 6 | 정정 · 보탬 · 후속 | 있을 때 | 4절 형식 |
| 7 | 미확인 | 있을 때 | 편집국이 확인하지 못한 것 |
| 8 | 끝줄 | 필수 | "침은 편집국 의견이며 행정 결정이 아닙니다." · 책임 표시 · 편집 마감 시각 |

E4(11/5) 하루는 실험표대로 Q를 1분 읽기 다음, 신호보다 앞에 둔다.

## 3. 신호 id

- 형식: `{지면 id}-s{번호}`. 지면 id는 직송판(editions.json)의 id와 같다. 예: `morning-20261030-s1`
- s1은 머리이고, 번호는 지면 순서대로 붙인다. E4처럼 순서를 바꾼 날에도 s1은 머리다.
- 발행 뒤에는 id를 바꾸지 않는다. 정정판에서도 같다. 정정으로 신호를 빼면 그 번호는 비워 두고 다시 쓰지 않는다.
- HTML로 낼 때는 신호 제목에 id를 단다. 예: `<h2 id="s1">`. 사이트 주소 형식은 Aside가 정한다.
- 정정·보탬·후속과 침의 행방은 신호 id로 가리킨다. 예: "제26호 s2(morning-20261030-s2)"
- 다른 지면도 같은 방식으로 쓴다. 예: `weekly-YYYYMMDD-s1`

## 4. 정정 · 보탬 · 후속

| 구분 | 언제 | 어디에 | 이미지 |
|---|---|---|---|
| 정정 | 발행한 사실이 틀렸을 때(숫자·날짜·기관명·인용·링크) | 같은 호를 "[정정판]"으로 다시 보낸다. 다음 호 텍스트판에도 한 줄 | 정정한 사실이 이미지에 있으면 다시 만들고 폴리오 위에 한 줄 |
| 보탬 | 틀리지 않았지만 조건·범위·맥락을 더할 때 | 다음 호 텍스트판 | 싣지 않음 |
| 후속 | 신호나 침에 새 소식(발표·시행·결과)이 생겼을 때 | 다음 호 텍스트판. 한 주 소식은 WEEKLY '지난 침, 이어 온 소식' | 싣지 않음 |

### 표기 문장 틀 — 무엇을 → 어떻게 · 왜 · 언제

```
[정정] 제26호 s2 · "고치기 전 문장" → "고친 문장" · 왜: (기관) 원문(발표 YYYY-MM-DD)과 다시 대조해 고침 · 언제: YYYY-MM-DD HH:MM 정정판 · 처음 판 보존
[보탬] 제25호 s1 · 무엇을 더했나: …… · 왜: …… · 근거: 기관, 자료명, 발표일, 링크
[후속] 제26호 s1 · 무엇이 이어졌나: (사실 한 문장) · 근거: 기관, 자료명, 발표일, 링크 · 침의 행방: 건넴 → 함께 봄 (확인된 경우만)
```

- **원판 보존.** 정정판은 새 판본으로 덧붙이고, 처음 판은 지우지 않는다. 직송판에서는 처음 본문을 `versions`에 `{ "label": "처음 판 · HH:MM", "body": … }`로 남긴다. 사이트는 이 칸을 '이전 판본 · 정정'으로 보여 준다. 반영은 Aside가 한다.

- **정정 대장.** 사이트 정정 대장은 `[정정]` 줄을 그대로 모은다. 그러니 줄 형식을 바꾸지 않는다.
- **정정판의 1분 읽기.** 1분 읽기 세 줄 위에 `[정정판] HH:MM · 무엇을 고쳤나` 한 줄을 따로 둔다. 세 줄은 고친 내용으로 바꾼다.
- **문체.** 정정은 편집국의 문장으로 쓴다("편집국이 원문과 다시 대조해 고쳤습니다"). 다른 기관이나 부서를 탓하는 말을 쓰지 않고, 긴 사과도 쓰지 않는다.
- **후속.** 확인된 소식만 쓴다. 소식이 없으면 쓰지 않는다. '미이행·지연·진행되지 않음' 같은 말은 쓰지 않는다. 침의 행방 단계는 부서가 알려 주었거나 공식 원문으로 확인된 때만 바꾼다.

## 5. 사이트 진열용 첫 세 줄 (1분 읽기)

텍스트판 맨 위 세 줄이다. 사이트 오늘 방과 링크 미리보기(og:description)가 이 세 줄을 그대로 쓴다.

| 줄 | 내용 | 형식 |
|---|---|---|
| 첫째 | 머리 신호의 변화와 닿는 공약 | "[무엇이 바뀌었나] — 닿는 공약 비전·○○." |
| 둘째 | 중랑에 적용한다면의 요지 | 중랑이 이미 하는 일에서 출발한 한 문장. 끝에 (편집국 의견) |
| 셋째 | 함께 생각해 볼 것 | Q의 요지 한 문장 |

E3(11/4)에는 실험표대로 둘째 줄을 '주민의 하루에서 달라질 장면'으로 시험한다. 제안 장면임을 밝힌다. 그 뒤의 형식은 실험 결과를 보고 발행인이 정한다.

- 한 줄에 한 문장, 50자 안팎으로 쓰고 마침표로 끝낸다.
- 그 줄만 읽어도 뜻이 서게 쓴다. '위 기사', '이 사례' 같은 가리킴말을 쓰지 않는다.
- 숫자는 본문과 같은 값과 단위로 쓴다. 링크와 출처 괄호는 넣지 않는다(출처는 신호 칸에).
- 부서 이름과 미비 지적형 문장을 쓰지 않는다. 중랑 지명은 둘째·셋째 줄에서만 쓴다.

### 직송판 필드 (제안, Aside 확인 뒤 확정)

지금 쓰는 필드(id, series, date, title, topic, desc, images, edition, desk, publishedAt, body)에 다음을 더한다. 확정 전에는 body의 순서만 지킨다.

```
"desc": "1분 읽기 첫째 줄",
"minute": ["첫째 줄", "둘째 줄", "셋째 줄"],
"pledges": ["비전·복지", "비전·걷기"],
"signals": [
  { "id": "s1", "title": "…", "pledge": "비전·복지", "link_type": "보완 제안",

    "src_type": "해외 도시", "url": "https://…", "published": "YYYY-MM-DD" }
],
"versions": [ { "label": "처음 판 · HH:MM", "body": "…" } ]
```

## 6. 미확인

- 대상의 상태가 아니라 편집국의 확인 상태로 쓴다. 예: "안심톡의 현재 운영 여부(원문 미확인)"
- 확인하지 못한 사실은 본문에 단정해 쓰지 않는다. 쓴 경우에는 이 칸과 짝을 맞춘다.

## 7. 발행 전 확인

- [ ] 0~8 순서와 칸 이름이 맞는가
- [ ] 신호마다 id, 닿는 공약, 원문 링크와 발표일이 있는가(발표일을 모르면 '발표일 미확인'과 확인일)
- [ ] 이미지에 있는 사실이 모두 텍스트판에 있는가
- [ ] 첫 세 줄이 5절 규칙을 지키는가
- [ ] 정정·보탬·후속을 구분했는가, 정정이면 처음 판을 보존했는가
- [ ] 평가로 읽힐 문장이 없는가
